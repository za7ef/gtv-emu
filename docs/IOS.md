# تطبيق iOS

يشغّل التطبيق محرك gtv-emu نفسه على iPhone وiPad، مع المترجم الفوري (JIT) حين يتاح، والمفسّر احتياطيًا حين لا يتاح.

## المكوّنات

| الجزء | الملف | الوصف |
|---|---|---|
| الواجهة البرمجية للمحرك | `core/gtv.h` و`core/gtv_api.c` و`core/host.h` | إنشاء الآلة وتشغيلها وإيقافها، وخطافات الطرفية والصوت والإطار، وأحداث الإدخال الآمنة من أي خيط |
| محرك التطبيق | `ios/GTVEmu/Engine/EmulatorEngine.swift` | يشغّل الآلة في خيط مخصص (مكدس 16 ميغابايت)، ويربط الخطافات بالواجهة |
| العرض | `ios/GTVEmu/Views/DisplayView.swift` | ‏MTKView يسحب أحدث إطار من virtio-gpu (صيغة BGRA) ويرسمه بنسبة 16:9، ويحوّل اللمس إلى شاشة اللمس الافتراضية 1280×720 |
| الريموت | `ios/GTVEmu/Views/RemoteView.swift` | أسهم واختيار ورجوع ورئيسية وقائمة وتشغيل ومستوى صوت وتشغيل/إطفاء، برموز مفاتيح لينكس عبر virtio-input |
| الصوت | `ios/GTVEmu/Engine/AudioOutput.swift` | ‏AVAudioEngine مع AVAudioSourceNode ومخزن حلقي، ويتبع معدل العينات الذي يختاره الضيف |
| الطرفية | `ios/GTVEmu/Views/ConsoleView.swift` | مخرجات المنفذ التسلسلي ورسائل المحاكي (يُحوَّل stderr إليها)، وسطر إدخال، وزر Ctrl-C، ومشاركة السجل |
| الصور | `ios/GTVEmu/Images/ImageStore.swift` و`ImagesView.swift` | قراءة manifest.json من إصدار GitHub، وتنزيل الملفات مع التقدم والتحقق من البصمة وفك ضغط gzip تدفقيًا، أو استيرادها من تطبيق الملفات |
| الإعدادات | `ios/GTVEmu/Views/SettingsView.swift` | الذاكرة (256 إلى 6144 ميغابايت) وعدد المعالجات (1 إلى 4) ووضع JIT ومصدر الصور ورمز الوصول |

## المترجم الفوري على iOS

يقرر `jit_alloc` في `core/jit.c` المسار كما يلي:

1. إن لم يكن هناك مصحّح مرفق (العلَم `CS_DEBUGGED` غير مضبوط) يعمل المفسّر وحده. لا يُنفَّذ أي `brk` في هذه الحالة، لأنه يُسقط التطبيق.
2. على iOS 26 وما بعده (أجهزة TXM، ومنها iPhone 16 Pro) يُستخدم بروتوكول StikDebug: تستدعي دالة صغيرة `brk #0xf00d` مع `x16 = 1` و`x0 = 0` و`x1 = الحجم`. يلتقط سكربت `universal.js` في StikDebug هذا التوقف، ويحجز منطقة RX ويهيئها لدى TXM، ويعيد عنوانها في `x0`. بعد ذلك ينشئ المحاكي نافذة كتابة للصفحات نفسها عبر `vm_remap` ثم `mprotect(RW)`.
3. على الإصدارات الأقدم: المسار القديم (`vm_allocate` لنافذة RW، ثم `vm_remap` وجعل النسخة RX).

يمكن فرض المسار من الإعدادات (تلقائي، TXM، القديم، معطّل)، وتظهر نتيجة آخر محاولة في الإعدادات وفي الطرفية.

مسار TXM مكتوب وفق السكربت المنشور في مستودع StikDebug (`StikDebug/Scripts/universal.js`، تحديث 2026-03-29)، **ولم يُجرَّب بعد على جهاز حقيقي**.

## التثبيت والتشغيل

1. شغّل سير العمل «تطبيق iOS» في GitHub Actions (أو ادفع تغييرًا إلى `ios/` أو `core/`)، ثم نزّل الملف `GTVEmu-unsigned.ipa` من مخرجاته.
2. ثبّته بأداة تثبيت جانبي توقّع بشهادة تطوير (SideStore أو AltStore أو Feather...). يجب أن يحمل التوقيع صلاحية `get-task-allow`، وهي موجودة في توقيعات التطوير عادة.
3. شغّل سير العمل «صور تطبيق iOS» مرة واحدة لنشر الصور في إصدار `images-v1` (فعّل خيار أندرويد إن أردته).
4. في التطبيق: الإعدادات ← مصدر الصور. المستودع خاص، لذا أضف رمز وصول GitHub بصلاحية قراءة المحتوى. ثم تبويب الصور ← تحديث ← «تنزيل الكل» لملف Alpine.
5. لتفعيل JIT: في StikDebug أضف السكربت `universal.js` لتطبيق GTV Emu (التطبيق ليس في قائمة الإسناد التلقائي في StikDebug)، ثم شغّله من StikDebug. بدون ذلك يعمل التطبيق بالمفسّر.
6. تبويب الآلة ← اختر «Alpine Linux (اختبار)» ← تشغيل. تظهر الطرفية فوق الشاشة بزر الطرفية، والصدفة الكاملة في تبويب الطرفية.

## ملفات الصور (manifest.json)

يبنيها `tools/mkios-assets.sh <مجلد> [--android]`، ويصف `manifest.json` كل ملف تعريف:

```json
{ "version": 1, "profiles": [ {
  "id": "alpine-test", "name": "...", "kind": "linux", "ramMB": 512, "cores": 2,
  "files": [ { "role": "kernel", "name": "alpine-Image.gz", "sha256": "...", "size": 9577960 },
             { "role": "initrd", "name": "alpine-initrd.gz", "sha256": "...", "size": 2458621 } ] } ] }
```

- الأدوار: `kernel` و`initrd` لملف تعريف لينكس، و`boot` و`vendor_boot` و`init_boot` و`disk` لأندرويد.
- `asset` اسم الملف في الإصدار إن اختلف عن الاسم المحلي، و`gunzip: true` لفك الضغط بعد التنزيل (صورة نظام أندرويد تُنشر مضغوطة).
- `url` رابط مباشر بديل عن ملفات الإصدار.
- يحمل التطبيق نسخة افتراضية من القائمة (`ios/GTVEmu/Resources/default-manifest.json`) حتى أول تحديث.

## البناء محليًا على macOS

```sh
brew install xcodegen
cd ios && xcodegen generate && open GTVEmu.xcodeproj
```

## ما اختُبر وما لم يُختبر

- **اختُبر على لينكس:** الواجهة البرمجية المضمِّنة كاملة عبر `tests/api_test.sh`، وهي الخطافات نفسها التي يستخدمها التطبيق. نجحت الاختبارات الست: الطرفية خروجًا ودخولًا، وزر الريموت، واللمس (ضغط وتحريك ورفع)، والصوت (24576 عينة بمعدل 48 كيلوهرتز)، ونسخ الإطار (1280×720). كما نجحت كل اختبارات `tests/boot_test.sh` بعد إعادة بناء واجهة سطر الأوامر فوق الواجهة الجديدة.
- **اختُبر بالترجمة فقط:** شيفرة C كلها، ومنها مسارا JIT الخاصان بـ iOS، تُترجم لـ `aarch64-macos`.
- **لم يُختبر:** شيفرة Swift لم تُترجم بعد، لعدم توفر Xcode محليًا، وأول تشغيل لسير العمل سيكشف أخطاءها. كذلك لم يُجرَّب التطبيق ولا مسار TXM على جهاز حقيقي.

## حدود معروفة

- تُنفَّذ المعالجات الافتراضية بالتناوب على خيط واحد، فزيادة عددها لا تسرّع المحاكاة.
- لا يمكن تشغيل أكثر من آلة في الوقت نفسه، لأن الأجهزة الافتراضية متغيرات عامة في المحرك. يمكن إيقاف الآلة وتشغيل أخرى، لكن إعادة تشغيل التطبيق أنظف.
- مع المفسّر وحده يستغرق أندرويد وقتًا طويلًا جدًا للوصول إلى شاشة الإقلاع. JIT ضروري عمليًا لمسار أندرويد.
- صلاحية `increased-memory-limit` لا تمنحها كل الشهادات. بدونها قد يُنهي النظام التطبيق إذا كانت ذاكرة الضيف كبيرة.
